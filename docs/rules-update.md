# Обновление требований DV Lottery

Требования хранятся в JSON-профилях в папке `Rules` рядом с `DvPhotoValidator.exe`. В исходниках это `src/DvPhotoValidator.Core/Rules/`. Программа загружает все файлы `*.json` из этой папки и показывает их в списке «Правила». Повреждённый профиль не загружается, а причина выводится в строке состояния.

## Порядок обновления перед выпуском

1. Откройте официальные страницы Государственного департамента США. Ссылки перечислены в поле `sources` профиля.
   - Photo Requirements
   - Digital Image Requirements
   - Photo Examples
2. Сверьте параметры:

   | Поле | Смысл | Значение в базовом профиле |
   |---|---|---|
   | `exportSize` | Сторона экспортируемого квадрата, px | 600 |
   | `minSize` / `maxSize` | Допустимая сторона готового фото, px | 600 / 1200 |
   | `maxFileBytes` | Лимит размера файла, байт | 245760 (240 КиБ) |
   | `headMinRatio` / `headMaxRatio` | Высота головы как доля высоты кадра | 0.50 / 0.69 |
   | `eyeMinRatio` / `eyeMaxRatio` | Высота глаз от нижнего края как доля | 0.56 / 0.69 |
   | `maxPhotoAgeMonths` | Максимальный возраст фото, месяцев | 6 |
   | `maxJpegQuality` / `minAcceptableJpegQuality` | Внутренние параметры экспорта | 95 / 70 |

3. Создайте новый файл, например `dv-2028.json`, с новым `id` и `rulesVersion`. Заполните `programYear` (например, `"DV-2028"`) и `verifiedOn` (дата сверки в формате `yyyy-MM-dd`). Профиль без `verifiedOn` показывается в программе с пометкой «не сверено с инструкцией».
4. Если какое-то требование изменилось качественно, а не только числом (например, появилось новое ограничение), добавьте правило: класс, реализующий `IValidationRule`, плюс регистрация в `ValidationEngine.CreateDefault()` и тесты.
5. Выполните `dotnet test`. Тест `RuleProfileTests` проверяет, что поставляемые профили загружаются без ошибок.

Изменение профиля не требует перекомпиляции. Достаточно положить JSON-файл в папку `Rules` установленной программы.
