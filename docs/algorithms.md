# Алгоритмы и ограничения (версия 0.1.0, этап 1)

## Конвейер обработки

1. **Чтение.** Файл целиком читается в память, исходник при этом не изменяется. Действуют лимиты 100 МБ и 100 Мп; оба настраиваются в `ImageLoadOptions`.
2. **Определение формата** по сигнатуре файла, а не по расширению: JPEG, PNG, BMP, TIFF, WebP, HEIF. WebP и HEIF декодируются, только если в Windows установлен соответствующий кодек из Microsoft Store.
3. **Декодирование** через Windows Imaging Component (WIC).
4. **Цвет.** Если встроен ICC-профиль, отличный от sRGB (Adobe RGB, CMYK и т. п.), пиксели преобразуются в sRGB. Файл без профиля считается sRGB. Прозрачные области накладываются на белый фон, и пользователь получает об этом предупреждение.
5. **EXIF Orientation.** Поддерживаются все 8 значений: изображение физически поворачивается и отражается.
6. **Кадрирование.** Квадратная рамка всегда остаётся внутри исходного изображения: пиксели за его пределами не дорисовываются. Обрезка и масштабирование выполняются за один проход сепарабельным фильтром Митчелла–Нетравали (B = C = 1/3). При уменьшении ядро расширяется, поэтому нет алиасинга и сильных ореолов по контуру.
7. **Экспорт JPEG.**
   - Сначала пробуется качество 95. Если файл не укладывается в лимит, бинарным поиском по диапазону 1–94 находится наибольшее качество, при котором размер ≤ `maxFileBytes` (по умолчанию 245 760 байт = 240 КиБ). Алгоритм детерминирован.
   - Файл пишется во временный файл в той же папке (`FileOptions.WriteThrough`).
   - Временный файл заново открывается с диска и проверяется: формат, размеры, цвет, цветовое пространство и фактический размер в байтах.
   - Если проверка не пройдена, экспорт отменяется, а существующий файл назначения не трогается. Если проверка пройдена, временный файл атомарно переименовывается в итоговый. Об успехе программа сообщает только после этого.
   - Если качество получилось ниже 70, выдаётся предупреждение «Качество сжатия».
   - Метаданные (EXIF, GPS) в итоговый файл не переносятся.

## Правила проверки

| RuleId | Группа | Что проверяется | Статусы |
|---|---|---|---|
| FILE_FORMAT | Техническая | Файл в формате JPEG | Pass / Fail |
| FILE_SIZE | Техническая | Размер ≤ maxFileBytes | Pass / Fail |
| DIMENSIONS_SQUARE | Техническая | Соотношение сторон 1:1 | Pass / Fail |
| DIMENSIONS_RANGE | Техническая | Сторона от 600 до 1200 px | Pass / Fail |
| COLOR_MODE | Техническая | Цвет, а не оттенки серого; 24 бита | Pass / Warning / Fail |
| COLOR_SPACE | Техническая | sRGB или файл без профиля | Pass / Fail |
| CROP_RESOLUTION | Визуальная | В рамке ≥ 600 px исходника (без растягивания) | Pass / Warning |
| HEAD_HEIGHT | Визуальная | (Yc − Yt) / H: от 50 до 69 % | Pass / Fail / ManualReview |
| EYE_HEIGHT | Визуальная | Линия глаз на высоте 56–69 % от нижнего края | Pass / Fail / ManualReview |
| HEAD_IN_FRAME | Визуальная | Верх головы и подбородок внутри кадра | Fail |
| PHOTO_AGE | Визуальная | Дата съёмки из EXIF не старше 6 месяцев | Pass / Warning / ManualReview |
| *_MANUAL | Визуальная | Фон, поза, глаза и выражение, очки и уборы, свет и резкость | ManualReview |

Технический статус файла и визуальный статус кадра выводятся отдельно. Общего балла нет. Группа получает худший статус среди своих проверок: Fail > ManualReview > Warning > Pass.

Если правило упало с ошибкой, отчёт строится дальше, а для этого правила выводится «Проверьте вручную».

## Измерение головы

- `Yt` — верх головы **вместе с волосами**, `Yc` — низ подбородка, `H` — высота кадра. Детектор лица на этом этапе не используется.
- Ориентиры ставит пользователь, перетаскивая линии в редакторе. Пока линия не поставлена, она пунктирная, а правило показывает ManualReview: программа не подставляет вымышленные координаты.
- Ориентиры хранятся в координатах исходника, поэтому при сдвиге и масштабе рамки они остаются на лице. Измерение пересчитывается при любом изменении.
- Точность ограничена тем, насколько аккуратно расставлены линии. При рамке 480 px на экране один экранный пиксель ≈ 0,2 % высоты кадра.

## Ограничения

- Фон, резкость, освещение, поза, состояние глаз, очки и головные уборы на этапе 1 не анализируются. Они всегда выводятся как «Проверьте вручную».
- Дата съёмки берётся из EXIF и может быть неверной. Поэтому старая дата даёт Warning, а не Fail.
- ICC-профиль считается sRGB, если в его описании встречается «sRGB». Это эвристика.
- Пороги правил — значения из ТЗ, хранятся в `Rules/dv-baseline.json`. До сверки с официальной инструкцией текущего года они не считаются подтверждёнными.
